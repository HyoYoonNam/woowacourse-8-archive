# REST Docs 글 독자 리뷰 기준

## 대상과 목적

- 대상: [원고](README.md) 전체
- 최초 검토 기준: `cd91baa0ecd6e85ab28fa6d5c5c2533ad5563110`
- Swagger를 사용하는 독자가 REST Docs 도입 이유와 추가 관리 비용을 판단할 수 있는지 확인한다.
- 리뷰 모델: Luna, Extra High

## 독자 설정

- Java와 Spring Boot 프로젝트 경험이 있는 학부생 또는 부트캠프 수료생 수준이다.
- Swagger 애노테이션 작성과 Swagger UI 요청 실행 경험은 있지만 OpenAPI 명세 생성과 UI 역할을 명확히 구분하지 못할 수 있다.
- JUnit과 Mockito로 간단한 테스트를 작성했고 MockMvc는 예제를 따라 사용한 정도다. @WebMvcTest의 범위는 익숙하지 않다.
- GitHub Actions로 테스트와 배포를 해 봤지만 Gradle 태스크 의존 관계와 CI 산출물 전달에는 익숙하지 않다.
- 저자와의 이전 대화, 책췍 개발 이력을 모른다.

## 검토 방법

1. 본문과 부록을 처음 읽는 독자로서 읽고 각 장에서 이해한 내용을 자기 말로 요약한다.
2. 처음 막힌 원문과 부족한 설명을 구체적으로 기록한다. 모르는 내용을 외부 자료로 보충해 이해한 것으로 처리하지 않는다.
3. 코드에서 무엇을 봐야 하는지, 실행 결과와 설명이 연결되는지 확인한다.
4. 도입 판단에 필요한 질문이 해소되는지, 제목이 장 전체를 요약하는지, 결론이 본문과 자연스럽게 이어지는지 확인한다.
5. 실제 독해에 영향을 주는 개선점 3~5개를 우선순위로 제안한다. 사소한 취향이나 기술적 오류 추측은 구분한다.

## 리뷰와 반영

- PR의 Files changed에서 해당 원고 줄에 리뷰 스레드를 만들고, 작성자 응답은 같은 스레드에 남긴다. 독자 역할을 맡은 에이전트의 리뷰임을 표시한다.
- 첫 리뷰에서는 원고를 수정하지 않는다. 채택한 의견은 후속 커밋으로 반영한다.
- 사용자 검토 전에는 PR을 머지하지 않는다.
